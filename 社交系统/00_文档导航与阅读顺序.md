# 社交系统文档导航与阅读顺序

## 1. 文档目标

这套文档用于「系统梳理与知识回顾」，重点帮助你回答以下问题：

- 聊天、好友、组队、公会这几套社交系统怎么分层？
- 哪些交互是请求-响应，哪些是转发推送，哪些是状态同步？
- 客户端 Manager / Service / UI 分别负责什么？
- 服务端如何处理在线转发、全局组织管理和玩家组件状态？
- 当前实现有哪些边界、风险和可优化点？

## 2. 推荐阅读顺序

### 2.1 主线阅读

1. `01_核心架构系统.md`
2. `02_聊天系统.md`
3. `03_好友系统.md`
4. `04_组队系统.md`
5. `05_公会系统.md`
6. `06_核心代码类.md`

### 2.2 最后复盘

7. `SocialSystem_CheatSheet.md`

> 建议：先通过 1 建立社交系统整体分层，再按 2~5 分别吃透聊天、好友、组队、公会，最后用 6 快速定位代码，用速记卡复盘。

## 3. 每篇文档用途

### 3.1 主体文档

- `01_核心架构系统.md`：看社交系统整体分层、客户端/服务端职责和交互类型。
- `02_聊天系统.md`：看频道分流、位运算过滤、私聊转发与群聊消息池。
- `03_好友系统.md`：看好友请求、双向确认、好友列表同步和在线状态更新。
- `04_组队系统.md`：看邀请入队、队伍生命周期和 TeamInfo 覆盖同步。
- `05_公会系统.md`：看公会创建、申请审批、成员管理和权限操作。
- `06_核心代码类.md`：按类名和职责快速定位实现文件。

### 3.2 复盘文档

- `SocialSystem_CheatSheet.md`：3 分钟复习提纲。

## 4. 建议长期维护的四类信息

1. **事实层**：当前代码实际如何运行，避免把“理想架构”和“现有实现”混淆。
2. **交互层**：哪些消息是直接转发，哪些是存储后拉取，哪些是全量覆盖同步。
3. **边界层**：在线依赖、权限校验、重复申请、并发点击等约束是否明确。
4. **演进层**：后续如果补离线消息、增量同步、权限细化时，应该落在哪一层。

## 5. 快速自检清单（复盘用）

- 我能在 60 秒内讲清楚社交系统的整体分层。
- 我能解释为什么聊天系统要做频道分流和位运算过滤。
- 我能说清好友/组队/公会申请为什么都带有“请求方 + 响应方”双向确认。
- 我能说清组队和公会为什么一个更像临时会话，一个更像持久组织。
- 我能指出至少 2 个当前实现边界，并给出优化方向。
