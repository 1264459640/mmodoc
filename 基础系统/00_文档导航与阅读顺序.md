# 基础系统文档导航与阅读顺序

## 1. 文档目标

这套文档用于「系统梳理与知识回顾」，重点帮助你回答以下问题：

- 背包、道具、装备、任务这四个系统怎么分层？
- 客户端哪些逻辑负责表现，哪些逻辑依赖服务端权威状态？
- 道具获得、装备穿脱、任务接提交流程分别怎么走？
- 为什么项目里要拆成 `Service / Manager / UI / Define` 多层结构？
- 当前实现有哪些边界、风险和后续优化点？

## 2. 推荐阅读顺序

### 2.1 客户端主线

1. `01_核心架构系统.md`
2. `02_背包与道具系统.md`
3. `03_装备系统.md`
4. `04_任务系统.md`
5. `05_核心代码类.md`

### 2.2 最后复盘

6. `BasicSystem_CheatSheet.md`

> 建议：先通过 1 建立整体分层，再按 2~4 分别吃透背包/装备/任务主链路，最后用 5 做代码定位，用速记卡复盘。

## 3. 每篇文档用途

### 3.1 主体文档

- `01_核心架构系统.md`：看基础系统整体分层、客户端与服务端边界、系统之间的关系。
- `02_背包与道具系统.md`：看 ItemManager、BagManager、ItemService 和背包 UI 的协作方式。
- `03_装备系统.md`：看 EquipManager 的引用共享设计、穿脱流程与属性联动。
- `04_任务系统.md`：看 QuestManager、QuesService、NPC 任务状态和接提交流程。
- `05_核心代码类.md`：按类名和职责快速定位实现文件。

### 3.2 复盘文档

- `BasicSystem_CheatSheet.md`：3 分钟复习提纲。

## 4. 建议长期维护的四类信息

1. **事实层**：当前代码真实如何运行，特别是哪些逻辑已经落地，哪些仍是占位实现。
2. **分层层**：Define、Model、Manager、Service、UI 的职责边界是否清晰。
3. **链路层**：购买、加道具、穿装备、接任务、交任务分别经过哪些对象。
4. **演进层**：当前实现的缺口，例如背包删除逻辑未补完、任务状态刷新依赖重建等。

## 5. 快速自检清单（复盘用）

- 我能在 60 秒内讲清楚基础系统的整体分层。
- 我能解释 `ItemManager` 和 `BagManager` 为什么要拆开。
- 我能说清装备为什么采用“引用共享”而不是复制一份数据。
- 我能说清任务系统里 NPC 状态是如何从任务状态推导出来的。
- 我能指出至少 2 个当前实现边界，并给出优化方向。
